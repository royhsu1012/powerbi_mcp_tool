# ⚡ PBI AI Bridge

讓 AI 代理（Claude Code 等）直接讀寫**執行中的 Power BI Desktop** 資料模型的本地橋接服務。

- **看得到**：AI 自己讀模型的資料表、欄位、量值與關聯，不用你貼給它
- **做得到**：量值直接寫進你開著的模型，寫完當場查詢驗算，數字不對自己修
- **管得住**：每個欄位的內容 AI 能看到多少由你決定，服務強制執行

> **其他文件**：[CLAUDE.md](CLAUDE.md) 是給 AI 的工作規範（Claude Code 自動載入），`docs\` 底下是它用到才讀的延伸規範；[AGENTS.md](AGENTS.md) 是 Codex / Cursor 等其他代理的入口；API 端點說明在 [API_Documentation.html](API_Documentation.html)（服務開著時從儀表板右上角開啟）。

## 這個工具解決什麼問題

請 AI 幫忙做 Power BI，平常是這樣：把資料表和欄位名稱貼給它 → 它寫一段 DAX → 你貼回 Power BI → 結果不對或跳錯誤 → 再把錯誤貼回去……
AI 從頭到尾**看不到你的模型，也不知道自己寫的公式算出來是多少**；而你為了讓它看懂，貼過去的截圖和資料裡常常帶著真實的客戶名稱與金額。

### 兩個互相拉扯的問題

1. **AI 看不到，所以幫不上忙。** 它不知道模型裡有哪些表、欄位叫什麼、關聯怎麼連，寫出來的公式是猜的；寫完也沒辦法自己跑一次看數字對不對，驗算全靠你
2. **讓它看，資料就出去了。** AI 是雲端服務，它讀到的每一個字都會離開這台電腦。模型裡是真實的客戶、訂單與成本，而 Power BI 沒有「只給結構、不給內容」的分享方式

結果多數人只能二選一：要嘛 AI 幫得上忙，要嘛資料不外流。**這個工具要做到的是兩個都要。**

### 為什麼 AI 看不到模型

模型不在對話裡。它在你電腦上 Power BI Desktop 的記憶體中，而聊天視窗裡的 AI 只看得到你貼進對話的東西。

Power BI 也沒有留一個讓外部 AI 連進來的入口：模型的引擎確實在本機開了一個連接埠，但那個埠每次開檔都不一樣，講的又是資料庫專用的協定。這個工具補上的就是這一段 —— 找到那個埠、連上去，再包成 AI 叫得動的簡單指令。

### 不用這個工具，直接讓 AI 改會怎樣

能在你電腦上讀寫檔案的 AI 代理，確實可以直接去改 Power BI 的檔案。三種做法比一比：

| | 把內容貼給聊天 AI | 讓 AI 代理直接改檔案 | 用這個工具 |
|---|---|---|---|
| AI 看得到模型嗎 | 只看得到你貼的 | PBIP 看得到結構，但是上次存檔的樣子；PBIX 看不到 | 看得到執行中的那一份 |
| 誰動手改 | 你自己貼回去 | AI 改檔案（只有 PBIP 改得了） | AI 寫進開著的模型，畫面立刻更新 |
| 寫錯了誰發現 | 你貼回去才知道 | Power BI 重新載入時才知道 | 引擎當場回報，AI 自己修 |
| 數字對不對 | 你自己看 | 你自己看 | AI 寫完自己查詢驗算 |
| 改名 | 你自己找所有引用 | AI 用文字搜尋，漏一處壞一處 | 由模型改寫所有引用，可以先預覽 |
| AI 讀到哪些資料 | 你貼什麼它看什麼 | 檔案裡有什麼它看什麼 | 每個欄位照你設的等級 |
| 改壞了 | Ctrl+Z | git 或自己備份 | 快照還原；一批變更有一步失敗就全部不套用 |

**同一件事 ——「幫我加一個毛利率量值」—— 兩條路各要走幾步：**

直接改檔案（只有 PBIP 做得到；PBIX 的模型包在壓縮的二進位資料裡，改不了）：

1. AI 讀專案資料夾裡的檔案。它看到的是**上次存檔時**的模型，你還沒存的修改不在裡面
2. AI 把量值寫進模型定義檔。檔案不會算、也不會報錯，寫對寫錯這時候沒有人知道
3. **Power BI 的畫面不會變。** 它用的是記憶體裡自己的那一份，磁碟上的檔案改了它不一定曉得
4. 你要讓它生效：不存檔、關掉 Power BI、重新開啟（資料量大的檔案每次都要等）。這段時間如果順手按了 Ctrl+S，Power BI 會把記憶體裡的舊版寫回磁碟，AI 剛改的內容就無聲無息被蓋掉
5. 重開之後才知道結果。公式有錯 → 那個量值報錯；檔案格式被改壞 → 整份專案打不開，要先把檔案修好
6. 錯誤訊息在你的螢幕上，AI 看不到 → 你複製貼回去給它 → 回到第 2 步
7. 沒報錯也不代表數字對。要驗算，只能你拉一個視覺來看，或截圖給 AI —— 真實資料就這樣出去了

用這個工具：

1. AI 讀**執行中**的模型（包含你還沒存的修改）
2. AI 把量值寫進去 → Power BI 畫面立刻多出這個量值。公式有錯，引擎當場回報，AI 自己修
3. AI 送查詢驗算（例如按產品線分組，對一下總數），數字不對就改到對
4. 你看過沒問題 → 存檔

除了步驟多寡，直接改檔案還有幾件事要知道：

- **Power BI 開著的時候，兩邊會打架。** 上面第 4 步的覆蓋實際發生過：AI 改了報表檔、Power BI 跳出「接受變更」的提示，但在按接受之前先送了 Ctrl+S，修改就不見了。改的是模型定義檔時，Power BI 會不會跳提示、會不會自己重新載入，這個工具沒有驗證過 —— 所以上面寫的是最保守的做法（關掉重開）
- **改名靠文字搜尋。** 一個欄位可能被幾十個量值和報表視覺引用，漏改一處就壞一處，而且要到重開才發現
- **做到一半失敗會留下半套檔案。** 改了十個檔案、第七個出錯，專案就停在一個不上不下的狀態
- **沒有人把關。** 檔案裡有什麼 AI 就讀到什麼：Power Query 腳本裡的連線字串與伺服器位址、報表篩選條件裡寫死的客戶名稱，整份進到 AI 那邊

這條路不是不能走。PBIP 可以搭配 git 看差異、隨時復原；報表版面本來就只能改檔案，這個工具也是這樣做（見[第 11 節](#11-目前的限制)）。但**模型的部分交給執行中的引擎比較好**：改完馬上知道對不對，AI 能自己驗算，而且它讀得到什麼由你決定。

一句話：**這個工具讓 AI 從「在旁邊出主意」變成「看得到模型、能動手做、做完自己驗算」，同時不讓真實資料外流。**

### 它能做什麼

- 讀寫**開著的**模型：量值、計算資料行、關聯、計算群組、RLS 角色、Power Query M……
- 執行 DAX 查詢**當場驗算** —— 寫完立刻查，不必存檔、不必重開
- 可同時開多個 PBIX / PBIP，隨時切換操作對象
- **資料保護**：AI 讀得到結構；每個欄位的內容它能看到多少，由你在儀表板逐欄決定。放寬保護、放行被擋下的查詢，都要你本人在 Windows 確認視窗按「是」
- 健檢：模型（壞掉的公式、雙向關聯、沒人用的欄位）與 PBIP 報表檔案（引用了不存在的欄位、視覺重疊）
- 改名時同步改寫所有引用；多個變更一次套用；動手前可以存快照
- **只有一個啟動檔**：缺什麼會先問你、按 Y 直接裝好；儀表板自動打開，不用貼金鑰

### 它不做什麼

- **不會把你的資料傳到任何地方**：服務只接受本機連線。唯一會離開電腦的是「AI 讀到的內容」，而那正是資料保護在管的東西
- 不修改 Power BI Desktop 本身，也不用裝外掛；關掉黑窗就完全停止
- 改動只進記憶體，**存檔才會寫進檔案** —— 不滿意就關掉不存
- AI 看不到畫面：報表版面好不好看、Power Query 預覽長怎樣，仍然要你看

## 運作原理

```
AI 代理（PowerShell）            瀏覽器（儀表板 http://localhost:5500/）
          ↕                            ↕
   HTTP + X-API-Key + X-PBI-Target   （只接受 localhost）
          ↕
   pbibridge_csharp/   C# 本地服務   ← 資料保護在這裡把關
          ↕  TOM（寫入）／ADOMD（查詢）
Power BI Desktop #1   Power BI Desktop #2   …
```

**① Power BI Desktop 自己就帶著一個資料庫引擎**

你開啟一份 .pbix／.pbip 時，Power BI Desktop 會在背景啟動一個 Analysis Services 引擎（`msmdsrv.exe`）。整份資料模型 —— 資料表、量值、關聯，連同資料本身 —— 都在這個引擎的記憶體裡。它在本機開一個隨機的連接埠，Power BI 的畫面就是透過這個埠跟它溝通的。

這個工具做的事說穿了很單純：**找到那個埠，用微軟官方的函式庫連上去。** 所以不需要外掛，也不修改 Power BI 本身。

**② 不記檔案路徑，每次都當場找**

服務的設定裡沒有任何「目標檔案」。每個請求進來時它才去查：現在有哪些引擎在跑 → 各自是哪一個 Power BI 視窗啟動的 → 那個視窗開的是哪個檔案。你換檔案、同時開好幾個，都不用改設定；開了多個而沒指定時它會拒絕執行，不會自己猜一個。

（檔案路徑是從 Power BI 的啟動參數讀到的，所以先開 Power BI 再從裡面選檔案時，它只認得報表的名稱 —— 見[第 5 節](#5-每天的使用流程)。）

**③ 兩條通道：一條改定義，一條查數字**

| 通道 | 用來做什麼 | 特性 |
|---|---|---|
| **TOM**（Tabular Object Model） | 讀寫模型的「定義」：量值、資料行、關聯、角色、Power Query | 改完 Power BI 畫面立刻更新；但改的是記憶體，**存檔才會進檔案** |
| **ADOMD** | 送出 DAX 查詢、拿回結果 | 唯讀。AI 寫完量值就用它驗算 |

**④ 包成只有本機連得到的 API**

服務把這兩條通道包成 `http://localhost:5500` 上的一組 API（讀模型、寫量值、查詢、改名、快照…）。AI 代理透過 `tools/PBI-Bridge.ps1` 呼叫；儀表板是同一組 API 的網頁介面。它只接受本機連線，每個請求都要帶金鑰，別的網站與別的 Windows 帳號都叫不動它。

一個完整的回合是：AI 讀模型 → 寫入量值（TOM）→ 查詢驗算（ADOMD）→ 數字不對就改到對 → 請 Power BI 存檔，並到磁碟上確認剛寫的內容真的在裡面。

**⑤ 資料保護：查詢送出之前擋一次，結果回來之後再擋一次**

唯一會離開這台電腦的是「AI 讀到的內容」，所以關卡設在服務裡、AI 與模型之間。分界線畫在**結構**與**內容**中間：表名、欄名、公式讓 AI 看（它要靠這些寫程式）；欄位裡的值能看到多少，照你替每一欄設的等級。

AI 送來的每一句查詢都會經過：

1. **展開**：查詢用到的量值、計算資料行、計算表，定義全部攤開來一起看 —— 把受限欄位藏進量值再查，一樣看得到
2. **檢查用法**：每個受限欄位出現在什麼位置？被計數函式包住、被加總、當分組鍵，還是直接取值？對照那一欄的等級，不合就不執行，回給 AI 原因與改寫建議
3. **處理結果**：檢查回傳的欄位、把設成「換成代號」的值換掉、列數封頂
4. **遮蔽錯誤訊息**：查詢出錯時，引擎訊息裡引用到的資料內容先遮掉才回給 AI

判斷不了的情況一律擋下：讀不到模型定義、設定檔壞掉，都當成「不放行」而不是「沒有限制」。規則一覽與它做不到的事見[第 8 節](#8-資料保護怎麼運作)。

**⑥ 為什麼有些事一定要你親手按**

AI 和儀表板用的是同一組 API、同一把金鑰 —— 技術上 AI 叫得動任何一個端點，包括「放寬保護」。光靠金鑰擋不住它替自己開門。

所以會讓 AI 看到更多內容的三件事（放寬欄位的等級、放行一句被擋下的查詢、經由 API 改寫 Power Query），服務會自己在你的螢幕上畫一個 Windows 確認視窗、列出內容。那個按鈕只有坐在電腦前的人按得到，API 按不到。

同樣的考量，API 金鑰與每個模型的逐欄設定都存在工具資料夾**之外**（`%LOCALAPPDATA%\PBI_AI_Bridge\`）—— 工具資料夾是 AI 平常讀寫檔案的地方，也是會被複製、分享出去的地方。

## 1. 快速開始

1. **下載並解壓縮**：在 GitHub 頁面按 **Code → Download ZIP**（會用 git 的話 `git clone` 也可以），解壓縮到本機資料夾，例如 `C:\PBI_AI_Bridge`。解出來的資料夾名稱（`powerbi_mcp_tool-main`）可以自己改。不要放 OneDrive，也不要在 zip 裡直接執行
2. 開啟一份 Power BI 檔案（.pbix 或 .pbip）—— 建議在檔案總管**雙擊檔案**來開，不要先開 Power BI 再從裡面選（原因見[第 5 節](#5-每天的使用流程)）
3. 雙擊 **`🚀啟動PBI終極儀表板.bat`**，照畫面回答 Y / N
4. 儀表板自動打開後，**保持黑窗開著**（關掉＝停止服務）
5. 到儀表板的「資料保護」分頁花一分鐘設定 AI 能讀哪些欄位（[第 4 節](#4-設定-ai-能讀哪些欄位重要)）
6. 在這個資料夾開啟 Claude Code，用中文告訴它你要做什麼

第一次視需要安裝的東西而定，約 2～5 分鐘；之後每次幾秒鐘。

> 💡 **強烈建議**：從 GitHub、Email 或 Teams 下載的 zip，**解壓縮前**先在 zip 上按右鍵 → 內容 → 勾選「解除封鎖」→ 確定。
> 不做的話，Windows 會把裡面每個檔案都標成「來自網際網路」：每次雙擊啟動檔都會跳安全性警告，自己在 PowerShell 執行 `tools\` 裡的腳本也會被擋（`is not digitally signed`）。啟動檔本身與 Claude Code 裡的 AI 不受影響。

## 3. 第一次啟動

只有一個啟動檔：`🚀啟動PBI終極儀表板.bat`。每次雙擊都依序檢查，**只做缺少的部分**：

| 檢查 | 第一次 | 之後 |
|---|---|---|
| 服務已經在跑？ | — | 是的話直接打開儀表板，不會重複啟動 |
| 1/5 檔案 | 確認資料夾完整；在 OneDrive 裡會警告 | 略過 |
| 2/5 .NET SDK | 沒有的話**問你要不要安裝** | 略過 |
| 3/5 設定檔 | 由範本產生 `appsettings.json`（裡面沒有金鑰或密碼） | 略過 |
| 4/5 套件 | NuGet 快取已經有就直接用；沒有才**問你要不要下載**（約 17 MB） | 略過 |
| 5/5 編譯 | 編譯（約 30 秒） | 程式有改才重新編譯 |

## 4. 設定 AI 能讀哪些欄位（重要）

欄位**名稱** AI 一定看得到（它要靠名稱寫公式）；這裡決定的是每個欄位**裡面的內容**它能看到多少。
沒設定過的模型只有「通用規則」在擋，而通用規則只認得英文欄名（`customer`、`amount`…）——
**模型如果用中文欄位名，幾乎全部都是開放的。** 請在讓 AI 查詢資料之前花一分鐘做完這一步。

### 三個步驟

儀表板 → 上方第二個分頁「資料保護」：

1. 按 **套用全部建議** —— 名稱像客戶、聯絡方式、備註、金額的欄位會先標成受限
2. 看一遍。用右上角的搜尋補漏（打「客戶」「金額」這類字），誤判的點回「開放」
3. 按 **儲存**

畫面跟上面說的不一樣時：

| 你看到的 | 原因與做法 |
|---|---|
| 沒有「套用全部建議」 | 這份模型沒有名稱可疑的欄位。建議是照欄名猜的，不代表沒有敏感欄位 —— 還是要看一遍 |
| 沒有「儲存」 | 它只在你改過至少一欄之後才出現在畫面下方 |
| 看完覺得都不用改 | 按提醒橫幅上的 **看過了，不用改**，分頁上的小圓點就會消失 |
| 個別建議不想套用 | 按那一欄的 **略過**，它維持開放、之後不再提示 |

「看過了」與「略過」只記在**這個瀏覽器**裡，不會存到服務 —— 服務分不出送出請求的是你還是 AI，記在那裡的話 AI 可以替你把提醒全部按掉。換瀏覽器或清除瀏覽資料之後，提醒會再出現一次。

### 四個等級

每個欄位右邊有四格，點一下就換等級。受限的欄位前面有鎖頭，往下掃一眼就知道哪些開放、哪些受限：

| 等級 | AI 可以 | AI 不行 | 適合 |
|---|---|---|---|
| **開放** | 直接讀內容 | — | 產品線、地區、日期 |
| **換成代號** | 計數、分組、排名；看到的是 `ID_3FA2B81C07` 這種代號 | 看到真正的名字 | 客戶、經銷商、業務員 |
| **只能計數** | 數有幾個、有幾筆是空的 | 列出內容、按它分組 | 電話、Email、地址、備註 |
| **只能彙總**（數字欄位） | 加總、平均、最大最小；按別的欄位分組來算 | 一筆一筆列出來 | 金額、單價、成本、薪資 |

- 「開放」每次最多回 50 列明細、300 列分組彙總，但多問幾次就讀得完 —— **請當作它全部看得到**
- 「換成代號」適合要分析到「每一個」、但不需要知道是誰的欄位：前 20 大客戶、集中度、流失名單
- 「只能彙總」按別的欄位分組時，結果最多 100 列（分得太細就等於逐筆）

欄位很多的時候：

- 搜尋是跨資料表的。搜「客戶」之後，清單上方會出現「把列出的 N 個欄位設為…」，一次設好
- 把某一欄設成受限時，如果別張表也有同名的欄位還開放著，下面會提醒你，可以一起設
- 這些批次動作都**只會收緊**。放寬要一欄一欄點

### 放寬要你本人確認

收緊（開放 → 受限）按儲存就生效。**放寬**時 Windows 會另外跳出一個確認視窗，列出要放寬哪些欄位，你按「是」才算數（為什麼需要這一步，見[運作原理 ⑥](#運作原理)）。

- 視窗沒出現？它可能在另一個螢幕，或沒有跳到最前面 —— 按 Alt+Tab 找，或看工作列
- 120 秒沒回答會當成「否」，之後 30 秒內不會再跳。收緊的部分不受影響，已經存好了
- **你沒有按儲存卻跳出放寬的視窗 → 按「否」**，然後問 AI 它想做什麼

### 設定存在哪裡

每個模型一份，存在這台電腦的 `%LOCALAPPDATA%\PBI_AI_Bridge\protection\`，不在工具資料夾裡。

設定跟著**模型本身**走，不是跟著檔名或資料夾。服務先找完整路徑相同的那一份；找不到就看內容 —— 設定檔記著模型裡一部分欄位的內部代號，打開的模型有同樣的代號就認得是同一份。所以這幾種情況設定都還在：

- 檔案搬到別的資料夾、改了檔名、另存新檔
- 先開 Power BI 再從裡面選檔案（這時服務拿不到檔案路徑，儀表板右上角顯示「路徑不明」）
- 同一份檔案複製成兩份 —— 兩份共用同一組設定，改其中一份另一份也跟著變

靠內容認出來的時候，「資料保護」分頁上方會有一行「這份模型沿用了先前存下來的設定」，並寫出當時的檔案。**看到這一行請掃一眼等級對不對** —— 它只把設定套到認得出來的同一個欄位上，之後新增的欄位照樣是沒設定過的。

從頭建立的另一份報表（就算表名、欄名都一樣）是不同的模型，要另外設定。

<details>
<summary>進階：通用規則（對每一個模型都生效的欄名樣式）</summary>

`pbibridge_csharp\appsettings.json` 的 `DataProtection` 段落有三張清單，依欄名樣式決定等級。逐欄設定優先於它們。

| 清單 | 等級 |
|---|---|
| `DenyColumns` | 只能計數 |
| `AggregateOnlyColumns` | 只能彙總（名稱符合但不是數字的欄位會當成只能計數） |
| `AllowColumns` | 開放（優先於上面兩張） |

- `*` 代表任意文字：`*客戶*` 會比對到「客戶名稱」「終端客戶」
- 比對時忽略大小寫、空白、底線、連字號：`account name`、`Account_Name`、`account-name` 視為同一個
- JSON 格式要正確（雙引號、逗號，最後一項後面不能有逗號）。改完要關掉黑窗、重新雙擊 🚀 才會生效

多數人不需要動這裡 —— 在儀表板用點的就夠了。要讓同一組樣式套用到你所有的報表時才需要。

</details>

### 驗證防護真的有效

服務與 Power BI 都開著時，請 AI 執行，或自己在工具資料夾的 PowerShell 跑：

```powershell
.\tools\Test-DataGuard.ps1                 # 只開一個 Power BI 時
.\tools\Test-DataGuard.ps1 -Target 61853   # 開了多個時指定 Port（黑窗「偵測到 N 個實例」那段看得到）
```

它拿你模型裡設成**「只能計數」**的欄位（至少要有一欄，沒有的話先到儀表板設一欄）模擬各種「偷看」手法，**只回報有沒有被擋下，不會印出任何資料**。最後一行是 `結果：N 通過 / 0 失敗` 就代表有效。
想更直接：請 AI「列出 5 個客戶名稱」—— 它應該會回報被擋下。

## 6. 跟 AI 協作

**開啟方式**：Claude 桌面版的 Code 分頁 → 選擇資料夾 → 選這個工具的資料夾；或在終端機 `cd C:\PBI_AI_Bridge` 後輸入 `claude`。
**一定要在這個資料夾開啟**，AI 才會自動讀到 `CLAUDE.md` 的工作規範（資料保護、防毒相容、驗算習慣）。第一次開啟時如果詢問是否信任這個資料夾，選信任。

第一句話可以說：「幫我檢查橋接服務，然後告訴我目前這份模型的結構」。

| 你想做 | 可以這樣說 |
|---|---|
| 了解模型 | 「這份模型有哪些事實表跟維度表？關聯怎麼接？」 |
| 健檢 | 「跑一次模型健檢，列出壞掉的公式和可能沒用到的欄位」 |
| 新增量值 | 「新增『毛利率』= [毛利] / [營收]，放在『量值』表，百分比格式，做完用產品線驗算」 |
| 修公式 | 「『年增率』在一月份是空白，幫我找原因並修好」 |
| 改名 | 「把『銷售額』改成『銷售總額』，先給我看會改到哪些公式」 |
| Power Query | 「『訂單』表的日期欄是 YYYYMMDD 文字，幫我寫轉日期的 M」 |
| 效能 | 「哪幾張表最佔記憶體？」「這個量值很慢，有沒有更快的寫法？」 |
| 多個檔案 | 「我開了兩個 Power BI，這次改『銷售報表』那個」 |

**好習慣**：確認 AI 選定時印出的完整路徑是你要改的那份（同名檔案常有好幾份）；大改之前說「先存快照」；要求「做完驗算給我看」；結束前確認已存檔。

### AI 會請你幫忙的五件事

有些事 AI **刻意不自己做**（為了資料保護，或避免觸發公司防毒），會停下來請你動手。這是正常的。

**① 確認視窗** —— Windows 跳出「PBI AI Bridge — 請確認…」

- 三種情況會跳：AI 想看一句被資料保護擋下的查詢、要放寬某些欄位的保護、或要改寫 Power Query
- AI 應該**先在對話裡說明**要做什麼、為什麼，視窗才跳出來；視窗會列出內容（哪些欄位、幾列、改什麼）
- 內容和它說的一樣、你也同意 → 按「是」。不同意、看不懂、或它沒先講 → 按「否」，再問它
- 預設是「否」，120 秒沒回答也算否。**AI 請你「按是就好」不算理由**

**② 讓 Power Query（M）生效** —— AI 可以直接寫 M，但只改到模型那一份

- AI 會問你 Power BI 有沒有出現「查詢中有暫止的變更尚未套用」。**有** → 按**套用**；**沒有**（兩種都遇過）→ 告訴 AI，它會自己重新整理那張表
- 之後 AI 會確認留下的是它寫的版本
- 你也可以請 AI 給完整的 `let … in`，自己貼進**進階編輯器**再「關閉並套用」。有問題就回 `錯`＋訊息，或 `怪`＋截圖（貼之前看一眼有沒有真實資料）

**③ 手動存檔** —— AI 回報沒存到（檔案沒變動，或找不到剛寫的內容）

- 切到 Power BI 按 Ctrl+S，然後告訴 AI。它會檢查磁碟確認，不會再送按鍵

**④ 重開服務** —— AI 改了伺服器程式或設定

- 關掉黑窗 → 告訴它 → 重新雙擊 🚀（程式有改會自動重新編譯）→ 告訴它

**⑤ 防毒警報**

- 先截圖並告訴 AI，它會說明剛才做了什麼。AI 被規範不能自己讀防毒紀錄

## 8. 資料保護怎麼運作

**AI 是雲端模型 —— 任何進入對話的內容都會傳到雲端。** 橋接服務只綁 localhost、不對外連線，唯一的外流管道是「AI 讀到了什麼」。
分界線：**欄位名稱可讀，欄位內容受管**。結構、關聯、健檢、每一欄的等級全開；被管制的是查詢的回傳值。一句查詢從送出到回傳會經過哪些關卡，見[運作原理 ⑤](#運作原理)。

### 規則

由伺服器端強制執行（`Program.cs` 的 `DataGuard`），違規回 403，AI 無法自我豁免：

- **每個欄位一個等級**（開放／換成代號／只能計數／只能彙總），由你在儀表板設定；沒設定的欄位照通用規則，再沒有就是開放
- **回傳列數封頂**：逐列明細 50 列、彙總 300 列、金額分組 100 列（呼叫端只能調低）
- **藏不住**：AI 把受限欄位包進量值、計算資料行、計算表或變數再查，伺服器會把定義展開來一起檢查
- **放寬、放行都要你按**：放寬欄位的等級、放行被擋下的查詢、經由 API 改寫 Power Query，都會在你的螢幕跳出 Windows 確認視窗，你按「是」才算數。Power Query 也算在內，是因為 M 可以把受限欄位的內容搬到開放的欄位裡
- **代號**：設成「換成代號」的欄位，值在離開這台電腦之前換成 `ID_3FA2B81C07` 這種代號。同一個值永遠是同一個代號、推不回原值；代號是誰只印在黑窗
- **錯誤訊息也管**：查詢碰到受限欄位而出錯時，訊息裡引用的資料內容會先遮掉才回給 AI
- **稽核記錄**：`audit\query-audit-YYYYMM.tsv` 記錄每一句查詢與判定、每一次設定變更與確認結果（不含回傳值）

代號是從 API 金鑰算出來的。金鑰換了（從舊版升級，或刪掉金鑰檔重新產生），代號會整批換新。

### 其他防線

- **服務連線**：所有 `/api/*` 都要帶金鑰；只接受以 `localhost` 連線（擋 DNS rebinding），不允許 `null` 來源（擋沙箱 iframe）—— 其他網站拿不到金鑰，也呼叫不了 API。金鑰存在你的使用者資料夾，這台電腦上別的 Windows 帳號讀不到
- **金鑰擋的是「別人」，不是 AI**：AI 的工具本來就要用金鑰呼叫 API。防 AI 的是上面那些伺服器端檢查，以及只有你按得到的確認視窗
- **Claude Code 的 hook 與權限規則**（`.claude/settings.json`）：hook 檢查 AI 要執行的 Bash／PowerShell **指令文字**，擋掉常見的繞路寫法（直接連引擎、手刻 HTTP 請求、指令裡出現保護設定資料夾）；權限規則禁止它的檔案工具讀寫金鑰與保護設定所在的資料夾。這一層只對 Claude Code 有效、看的是文字與路徑，是輔助而不是保證

### 實際會發生什麼

| 情況 | 結果 |
|---|---|
| AI 查「有幾個客戶」、「各產品線營收」 | ✅ 回傳數字／彙總 |
| AI 想列出客戶名稱、逐筆看金額 | ⛔ 擋下，AI 會改用計數或加總 |
| 客戶名稱設成「換成代號」，AI 查前 20 大客戶 | ✅ 回傳 20 個代號與金額；誰是誰看黑窗 |
| 查詢結果超過 50 列明細／300 列彙總 | 只回傳到上限，AI 會知道結果被截斷 |
| AI 確實需要看被擋下的內容 | 它會先向你說明，然後你的螢幕跳出確認視窗 —— 由你決定 |

### 這套機制做不到、你自己要注意的

- **「開放」就是看得到**：逐列明細每次 50 列、分組彙總 300 列，多問幾次就讀得完。不想讓 AI 看的欄位請設成受限，不要靠列數上限
- **沒設定過的欄位預設是開放**：模型新增了敏感欄位，或開了一份從頭建立的新報表，記得回「資料保護」分頁設定
- **條件很窄的彙總等於明細**：「某某公司上個月營收」雖然是加總，其實就是那家公司的數字
- **「只能計數」擋的是列出與分組**：AI 仍然可以問「有沒有叫某某的客戶」這種答案是數字的問題
- **「換成代號」不是加密**：同一個客戶永遠是同一個代號，客戶不多或特徵明顯時，從金額與地區還是猜得出是誰
- **M 腳本管不到**：裡面可能有寫死的客戶名稱與連線字串。AI 被規範成預設只存檔、不讀內容，但這條靠的是規範而不是伺服器
- **你自己貼給 AI 的截圖與文字不在管制範圍內**，貼之前先看一眼

## 9. 快照與還原

AI 在刪除、改名等破壞性操作前會自動存快照。你也可以隨時要求：「先存一個快照，標籤叫『改版前』」、「還原到『改版前』，只還原量值，先給我看會改什麼」。

快照存在 `snapshots\<檔名>_<雜湊>\`，每份模型各自獨立，不會還原到別的模型上。還原**不是**完整的時光機：

- 只還原量值、計算資料行、關聯、共用運算式、M 腳本
- 快照之後**新建的表格、角色不會被刪掉**
- 快照裡沒有的量值與關聯**會被刪掉**（回到當時狀態，不是合併）
- 還原 M 之前會先跳確認視窗，還原之後還要讓 M 生效（見[第 6 節](#6-跟-ai-協作)的 ① 與 ②）。只想動量值就請 AI「只還原量值」
- 從 Power BI 裡面開啟的檔案（儀表板顯示「路徑不明」）存的快照，只在這次開啟期間找得到；要留快照請用雙擊檔案的方式開啟

快照只是模型定義的備份，**不能取代存檔**。重要的報表請另外自己備份 .pbix / .pbip。

## 10. 自己用 PowerShell 操作

不透過 AI 也可以直接用。在工具資料夾開 PowerShell：

```powershell
. .\tools\PBI-Bridge.ps1                        # 載入（會列出所有可用指令）
Get-PbiOverview                                 # 一次看完：選定的檔案、模型大小、健檢、資料保護
Get-PbiOverview 銷售報表                          # 開了多個 PBI 時，用檔名片段或 Port 選定
New-PbiSnapshot -Label before                   # 動手前留退路
Set-PbiMeasure -Table 量值 -Name 銷售總額 -Expression 'SUM(FactSales[Amount])' -Format '#,0'
(Invoke-Dax 'EVALUATE ROW("結果", [銷售總額])').Rows   # 立刻驗算
Save-PbiModel -Expect '銷售總額'                  # 存檔，並確認剛寫的量值真的進了磁碟（expectFound = true）
```

**不要自己手刻 `Invoke-RestMethod`**：PowerShell 5.1 預設不以 UTF-8 送出，中文欄位名與 DAX 會壞掉；`PBI-Bridge.ps1` 已處理好。

### 存檔

**修改只進記憶體**：畫面立刻更新，但要寫進 `.pbix` / `.pbip` 必須 `Save-PbiModel`（或手動 Ctrl+S）。

`Save-PbiModel` 會回報哪些檔案變了（`changedFiles`）。但「檔案有變」不等於「剛寫的東西進去了」—— Power BI 還沒同步到剛才的寫入時，存下去的是舊狀態。所以 PBIP 請加 `-Expect '<剛寫的量值名稱>'`，看 `expectFound`。結果不確定時用 `Save-PbiModel -VerifyOnly -Expect …` 回頭檢查磁碟，它不會送按鍵。

### 什麼時候要 refresh

結構性變更後要 refresh 才查得到：

| 做了什麼 | 需要 refresh 嗎 |
|---|---|
| 新增／修改量值 | 不用 |
| 建計算表、新增計算項目 | `Invoke-PbiRefresh -Table <表>` |
| 建／改關聯、新增計算資料行 | `Invoke-PbiRefresh -RefreshType calculate` |
| 用 `Set-PbiMQuery` 改 M 腳本 | Desktop 出現「暫止的變更」提示 → 按「套用」。**沒出現** → `Invoke-PbiRefresh -Table <表>` |
| M 多輸出了一個新欄位 | 先 `Add-PbiColumn … -SourceColumn <欄>`，再 `Invoke-PbiRefresh -Table <表>` |

`Invoke-PbiRefresh` 是跑完才回應的（回應裡有實際耗時），收到就可以直接驗算。

## 11. 目前的限制

| 項目 | 狀態 | 說明 |
|---|---|---|
| DAX 量值／計算資料行／關聯／計算群組／RLS | ✅ | 完整 |
| Power Query M | ✅ | 可讀可寫，但寫入之後要讓它生效（見下方） |
| 資料保護設定 | ✅ | 跟著模型走。從頭建立的另一份報表要另外設定，尚未提供「把設定複製給另一份」 |
| 報表版面（視覺） | 🟡 | 沒有寫入用的 API，PBIP 可以直接改檔案（見下方） |
| M 預覽／查詢摺疊分析 | 🟡 | 未實作。套用後可用 `Get-PbiTableProfile` 做量化檢查（列數、空值、相異值、總和） |
| 從 Power BI 裡面開啟的檔案 | 🟡 | 服務拿不到檔案路徑，部分功能不能用（見[第 5 節](#5-每天的使用流程)） |
| 階層、檢視方塊、KPI、多語系、增量重新整理原則 | ❌ | 未實作 |

**Power Query M**

- 資料保護啟用時，寫入前會先跳確認視窗
- 寫入只改模型那一份，而且不會重抓資料。之後 Power BI 有時會顯示「查詢中有暫止的變更尚未套用」（按**套用**），有時完全沒有提示（要對那張表 `Invoke-PbiRefresh`）—— 兩種都遇過
- 兩份內容不同時，套用有可能以 Power BI 那份為準，所以生效後要確認留下的是預期版本
- M 多輸出的新欄位要用 `Add-PbiColumn -SourceColumn` 補進模型
- 直接改 PBIP 的模型定義檔（TMDL）這條路尚未實作

**報表版面**

- PBIP 可以讓 AI 直接改報表資料夾裡的檔案，你在 Power BI 按「接受變更」；改完用 `Test-PbiReport` 檢查有沒有改壞
- 接受變更之前不要存檔 —— Ctrl+S 會把 Power BI 記憶體裡的舊版面寫回去，蓋掉 AI 的修改
- **AI 看不到畫面**，文字有沒有被擠壓、好不好看要你截圖給它

**已移除的功能**：`/api/inject-visual`（強制關閉並重開 Power BI，會觸發防毒）、查詢的 `-Pseudonymize` 與 `-DetailToken` 參數（改成逐欄的「換成代號」等級與確認視窗）。舊腳本呼叫它們會得到 404 或參數錯誤。

## 13. 疑難排解

### 啟動與安裝

| 症狀 | 處理 |
|---|---|
| 雙擊 .bat 跳「開啟檔案 - 安全性警告」或「Windows 已保護您的電腦」 | 從網路下載的檔案都會這樣。前者按「執行」，後者按「其他資訊」→「仍要執行」。想以後都不再跳：刪掉解出來的資料夾，在 zip 上按右鍵 → 內容 → 勾「解除封鎖」後重新解壓縮 |
| 啟動檔找不到 .NET SDK | 按 Y 讓它用 winget 安裝；不行就按 O 手動安裝「.NET SDK 8.x.x」，裝好按 R。見[第 3 節](#如果問你要不要安裝-net-sdk) |
| 啟動檔 4/5 下載失敗 | 見[套件下載失敗](#套件下載失敗) |
| `[WARNING] This folder is inside OneDrive` | 建議把資料夾搬到本機，例如 `C:\PBI_AI_Bridge` |
| 編譯失敗，訊息有 `being used by another process`（`MSB3027` / `CS2012`） | 同時有兩個啟動檔在編譯。關掉多的黑窗再雙擊一次 |
| `Port 5500 is used by a different program` | 別的程式占用 5500（例如 VS Code Live Server）。關掉它再雙擊 🚀 |
| 黑窗顯示 `[EXIT] Server stopped` | 往上捲看錯誤。改過 `appsettings.json` 的話先檢查 JSON 格式（逗號、引號） |
| 改了 `appsettings.json` 沒生效 | 關掉黑窗、重新雙擊 🚀 |
| 載入工具時出現一堆 `Unexpected token` 亂碼 | `.ps1` 被存成沒有 BOM 的檔案。VS Code 開啟 → 右下角編碼 →「以 UTF-8 with BOM 儲存」 |

### 連線與儀表板

| 症狀 | 處理 |
|---|---|
| 儀表板顯示「無法讀取模型」 | 確認黑窗開著、Power BI 有開檔案；開了多個就在右上角選一個 |
| 儀表板顯示「金鑰不符」 | 服務重新啟動過，按 F5 重新整理頁面 |
| AI 或 PowerShell 工具說「找不到 API 金鑰檔」 | 金鑰是服務啟動時產生的。服務還沒啟動過，或黑窗裡跑的是舊版：關掉黑窗、重新雙擊 🚀 |
| 黑窗提示 `appsettings.json` 裡還留著舊版的 `Security.ApiKey` | 從舊版升級上來的。那一把已經失效，把那一行刪掉即可（不刪也不影響使用） |
| `找不到正在執行的 Power BI 檔案` | 先開啟 .pbix / .pbip |
| `目前有 N 個 Power BI 實例在執行` | 告訴 AI 要改哪一個（或 `Use-PbiInstance <檔名片段或 Port>`）。同一份檔案開了兩次也會這樣，關掉多的那個視窗 |
| 儀表板右上角的檔案顯示「路徑不明」 | 這份檔案是先開 Power BI、再從裡面選的。能做與不能做的事見[第 5 節](#5-每天的使用流程)；要解除限制就關掉 Power BI，改用**雙擊檔案**的方式開啟 |
| 儀表板顯示「（未開啟檔案）」，或「資料保護」說認不出這份報表 | Power BI 開著但還沒有載入檔案，或是一份還沒存過的空白報表。開啟檔案（或先 Ctrl+S 存檔）後按「重新掃描」 |

### 資料保護

| 症狀 | 處理 |
|---|---|
| 「資料保護」分頁上有一個小圓點 | 這份模型還沒設定過、有建議還沒處理，或有變更還沒儲存。照[第 4 節](#4-設定-ai-能讀哪些欄位重要)做一次；都不用改就按橫幅上的「看過了，不用改」 |
| 找不到「套用全部建議」或「儲存」 | 前者：這份模型沒有名稱可疑的欄位。後者：改過至少一欄才會出現在畫面下方 |
| 上方寫「這份模型沿用了先前存下來的設定」 | 正常：檔案換過位置、改過檔名，或這次是從 Power BI 裡面開的。掃一眼等級對不對即可 |
| 按了儲存，確認視窗沒有出現 | 它可能在另一個螢幕，或沒有跳到最前面：按 Alt+Tab 找，或看工作列。120 秒沒回答會當成「否」，要再等 30 秒才能重送；收緊的部分已經存好了 |
| 沒有人按儲存，卻跳出「請確認要放寬資料保護」 | 按「否」。那是程式（通常是 AI）在要求放寬 —— 問它想做什麼、為什麼 |
| 顯示設定檔讀不出來，AI 的查詢全部被擋 | 設定檔損毀。按橫幅上的「重設」（會跳確認視窗），再重新設定一次 |
| 顯示資料保護是關閉的 | `appsettings.json` 的 `DataProtection` → `Enabled` 是 `false`。改成 `true`，關掉黑窗、重新雙擊 🚀 |
| AI 說查詢被擋下（403） | 正常：它碰到你設成受限的欄位了。多半它會自己改用計數或加總；真的需要看內容時它會先說明，再由你在確認視窗決定 |

### 存檔與 Power Query

| 症狀 | 處理 |
|---|---|
| 存檔回報 `fileChanged = false` | 30 秒內檔案沒有變動：本來就沒有待存的變更、按鍵沒送達，或大檔還在寫。稍等後用 `Save-PbiModel -VerifyOnly -Expect …` 檢查（不送按鍵）；確定沒存到就手動 Ctrl+S，**不要連按** |
| 存檔回報 `expectFound = false` | 檔案有寫，但剛改的內容不在裡面 —— Power BI 還沒同步到 AI 的寫入就存了。等幾秒再存一次（AI 最多重試一次），或手動 Ctrl+S |
| AI 說沒辦法存檔，因為不知道檔案路徑 | 這份檔案是從 Power BI 裡面開的。自己按 Ctrl+S；之後改用雙擊檔案的方式開啟 |
| Power BI 顯示「查詢中有暫止的變更尚未套用」 | M 被 API 改過。按「套用」即可更新；套用後確認 M 是你要的版本，不是的話到進階編輯器貼上正確的 M 再「關閉並套用」 |
| AI 改了 M，Power BI 沒有任何提示，資料也沒變 | 寫入只改模型裡的 M，不會自己重抓資料。請 AI 對那張表重新整理（`Invoke-PbiRefresh -Table <表>`） |
| AI 直接改了報表檔，接受變更後又變回舊的 | 接受之前有人按了 Ctrl+S，舊版面被寫回磁碟。請 AI 從備份還原再改一次，這次先接受變更再存檔 |

### 防毒警報

停止操作、截圖、記下時間，告訴 AI 與 IT。詳見 CLAUDE.md「防毒軟體相容規範」。

### PowerShell 無法執行腳本

錯誤訊息類似「因為這個系統上已停用指令碼執行」或「檔案未經數位簽署」（英文介面是 `running scripts is disabled` 或 `is not digitally signed`）。依序嘗試：

1. **解除下載封鎖**（最常見）—— 在工具資料夾開 PowerShell 執行：
   ```powershell
   Get-ChildItem .\tools, .\.claude\hooks -Filter *.ps1 | Unblock-File
   ```
2. **只對目前使用者放寬執行原則**：
   ```powershell
   Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
   ```
3. 仍被公司原則（群組原則）鎖住 → 請洽 IT，不要自行想辦法繞過

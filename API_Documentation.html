PBI AI Bridge API 文件

38 個端點 · 支援同時操作多個 Power BI · 全域受 X-API-Key 保護（/ping 除外）· 僅綁 localhost:5500

返回動態探索儀表板

這是通用工具：先選定要操作哪一個 Power BI

一台機器可以同時開好幾個 Power BI Desktop，每一個都有自己的 msmdsrv 子行程與連接埠。 本服務**不綁定**任何特定檔案 —— 所有路徑都在每次請求時從執行中的行程即時推導 （msmdsrv.ParentProcessId → PBIDesktop → 命令列 → 開啟的檔案）。

請求用 X-PBI-Target 標頭指定目標，值可以是 Port 數字或檔名/路徑片段：

  • 只有一個實例 → 可以不帶，自動採用
  • 多個實例卻沒指定 → 一律回 400 並列出清單，連讀取也拒絕。 猜錯的代價是改到別的模型，所以寧可回錯誤也不預設挑一個
  • 片段同時符合多個 → 回 400，要求改用 Port 精確指定

⚠️ HTTP 標頭只能放 ASCII，中文檔名不能直接當標頭值 —— Use-PbiInstance 內部一律換算成 Port 再送出，並記住完整路徑， PBI 關掉重開（Port 會變）時自動重新解析。

開始之前，兩件必須知道的事

1. 寫入只進記憶體，不會自動存檔。 TOM 的 SaveChanges() 只改 Power BI Desktop 記憶體中的模型。要落到 .pbix/.pbip 必須呼叫 /api/save，並確認回傳的 fileChanged 為 true。

2. 結構性變更後必須重算，否則查不到資料。 只寫量值不用重算；但建立計算表、關聯線、計算項目之後，不跑 /api/refresh 查詢就會回「需要重新計算，因此未包含任何資料」。

做了什麼要跑什麼耗時
建立計算表 / 計算項目refresh（指定該表）秒級
建立或修改關聯線 / 計算資料行refresh + RefreshType: "calculate"秒級
改寫 M 腳本refresh（該表，full）可能很久，要重抓資料源

第壹部：讀取與診斷 GET · 唯讀，隨時可呼叫

GET免 Key

/ping

健康檢查

回傳 pong 代表服務就緒。這是唯一不需要 X-API-Key 的端點。

GET

/api/schema

全域結構掃描

所有資料表、欄位（含資料類型、DisplayFolder、SortByColumn）、DAX 量值原始碼、計算項目，以及 Power Query M 腳本。

M 腳本含連線字串與伺服器位址，非必要不要整包倒進 AI 的對話。
GET

/api/relationships

關聯模型透視

所有關聯線的來源／目標欄位、基數、跨篩選方向、是否啟用。

GET切換檔案的第一站

/api/instances

列出所有執行中的 Power BI

每個實例回傳 Port、PbiPid、MsmdsrvPid、 FilePath、FileName、WindowTitle、 Kind（PBIX / PBIP / Unknown）。

這是唯一不需要指定目標的實例相關端點 —— 你得先看到清單才能選。

PowerShell：Get-PbiInstances / Use-PbiInstance <片段或 Port>
GET

/api/pbi-info

你到底在改哪個檔案

回報目前這次請求解析到的目標實例：檔案路徑、格式、Port、行程 ID。

同一台機器常有多份同名 .pbip / .pbix（例如桌面一份、專案資料夾一份）—— 動手前先確認，改錯檔案比改錯公式難救。

GET

/api/validate

模型健檢

引擎回報的壞掉公式、雙向／多對多關聯、停用關聯、跨表重複的量值名稱、沒有格式字串的量值、孤島表、自動日期表數量、疑似沒人用的欄位、用了彙總函式的計算資料行。

只有 BrokenObjects 是「確定壞掉」（引擎回報），其餘皆為建議。PossiblyUnusedColumns 只比對 DAX 文字，未涵蓋報表視覺，刪除前務必人工確認。
GET

/api/model-props

模型層級屬性

模型名稱、DiscourageImplicitMeasures、相容性層級、計算群組數量。

GET

/api/roles

RLS 角色清單

所有資料列層級安全性角色、權限等級，以及每個角色的資料表篩選規則。

GET

/api/expressions

Power Query 共用運算式

模型層級的 M 參數與共用函式（不屬於任何單一資料表的那些）。

GET

/api/snapshots

快照清單

只列出目標實例自己的快照，最新的排最前面。

第貳部：查詢引擎 POST · 唯讀，寫完量值用來驗算

POST

/api/query

唯讀 DAX 查詢

查詢必須以 EVALUATE 或 DEFINE 開頭（唯讀防護，擋掉會變更模型的 XMLA 命令）。回傳欄位清單、列數、是否截斷，以及 ElapsedMs。

DAX 語法錯誤回 400，body 含引擎原始訊息與錯誤位置，可直接據此修正公式。

{ "Query": "EVALUATE ...", "MaxRows": 1000, "TimeoutSeconds": 60 } 資料保護（伺服器端強制）：客戶身分欄位只准出現在計數類函式內（DISTINCTCOUNT／COUNTROWS…），金額欄位必須包在聚合函式內，違者回 403。管制清單見 appsettings.json 的 DataProtection。被擋下時服務主控台會印出一次性權杖，經使用者確認後以 X-PBI-Allow-Detail 標頭放行「同一句」查詢（10 分鐘、限用一次）。
POST

/api/dmv

系統檢視查詢

執行 $SYSTEM DMV，用於效能分析與相依性追蹤。這些檢視只含中繼資料與統計，不會回傳事實資料列。

格式必須是 SELECT ... FROM $SYSTEM.<檢視>，白名單以外一律拒絕。

SELECT DIMENSION_NAME, COLUMN_ID, USED_SIZE FROM $SYSTEM.DISCOVER_STORAGE_TABLE_COLUMN_SEGMENTS $SYSTEM.TMSCHEMA_PARTITIONS 會回傳 M 腳本（含連線字串），非必要不要查它。

第參部：安全網 破壞性操作前先做這個

POST

/api/snapshot

模型快照

把整個模型定義序列化成 TMSL JSON 存檔，附時間戳與自訂標籤。刪除、改名、覆寫 M 腳本之前都該先跑一次。

每個模型有自己的資料夾：snapshots/<檔名>_<路徑雜湊>/。 路徑雜湊是必要的 —— 桌面的 X.pbix 和專案裡的 X.pbip 檔名相同但是完全不同的模型，混在一起會互相污染。

{ "Label": "before-refactor" }
POST會刪東西

/api/restore

從快照還原

還原量值、計算資料行、關聯線、M 腳本、共用運算式。支援 DryRun 先看差異清單。

還原不是合併，是回到當時的狀態 — 快照中不存在的量值與關聯會被刪掉。
另外它不會刪除表格與角色，也不改模型層級屬性；沒被涵蓋的項目會列在回應的 Uncovered 裡，別忽略。 只在目標模型自己的快照資料夾裡找檔案， 路徑分隔字元一律拒絕 —— 結構上就不可能把 A 模型的快照還原到 B 模型。 { "File": "20260805_121110__before.json", "DryRun": true }

第肆部：讓變更生效 不跑這兩個，改了等於沒改

POST

/api/refresh

重新整理資料

不指定 TableName 就是整個模型。RefreshType 可用 full／calculate／dataOnly／automatic／ add／clearValues／defragment。

calculate 只重算 DAX、不重抓資料源，很便宜 — 結構性變更後直接跑一次就好。

{ "TableName": "銷售", "RefreshType": "full" }
POST

/api/save

模擬 Ctrl+S 存檔

把目標那一個 PBI Desktop 帶到前景送出 Ctrl+S，再比對檔案修改時間驗證是否真的存到。

驗證對象是該實例自己的檔案；.pbix 直接看單一檔案時間， .pbip 則掃整個專案資料夾（存檔會散落在 .Report / .SemanticModel）。

一定要看回傳的 fileChanged。false 代表沒存到（或本來就沒有待存變更），不要當成成功。
會短暫搶走鍵盤焦點 — 這是 SendKeys 的固有限制。

第伍部：量值與資料行 POST · 會改動模型

POST

/api/upsert-measure

新增或覆寫量值

同名者直接覆蓋。可設定 DAX 公式、格式字串、說明、DisplayFolder 與 IsHidden。未指定的屬性維持原值。

{ "TableName": "量值", "MeasureName": "銷售總額", "Expression": "SUM(f[Amount])", "FormatString": "#,0", "DisplayFolder": "核心指標" }
POST不可復原

/api/delete-measure

刪除量值

刪除指定量值。無法復原 — 執行前先建快照。

POST

/api/move-measure

量值搬家

把量值從 A 表搬到 B 表，公式與所有屬性一併帶走。若目標表不存在，會自動建立一張量值專用空殼表。

POST

/api/add-column

新增計算資料行

用 DAX 新增計算資料行。DataType 可用 text／int／decimal／currency／bool／date。同名計算資料行會被覆寫。

新增後需要 refresh（calculate）才會有值。
POST不可復原

/api/delete-column

刪除資料行

仍被關聯線使用時會被擋下，需先刪關聯。

若刪的是來源資料行（非計算），下次重新整理時可能會依 M 腳本重新出現。
POST

/api/set-column-props

資料行屬性

格式字串、DisplayFolder、隱藏、SortByColumn、SummarizeBy、資料類別、說明。只送出有指定的欄位，其餘維持原值。

只有計算資料行能改資料類型；來源資料行的類型由 Power Query 決定，要改請改 M 腳本。

第陸部：表格與改名 POST · 結構性變更

POST

/api/create-table

建立新表格

Kind: "calculated" — 用 DAX 建計算表，資料行由引擎自動推導。
Kind: "m" — 用 M 腳本建表，必須同時指定 Columns（引擎不會替 TOM 建立的 M 表推導結構）。
Kind: "measureHolder" — 只放量值的空殼表。

{ "TableName": "指標", "Kind": "calculated", "Expression": "DATATABLE(\"k\", STRING, {{\"a\"}})" } 建立後需要 refresh 該表，否則查詢會回「未包含任何資料」。
POST不可復原

/api/delete-table

刪除表格

連同表上的所有量值一併刪除。仍有關聯線指向它時會被擋下並列出是哪幾條。

POST

/api/rename

改名 + 同步改寫 DAX 引用

支援 measure／column／table。TOM 本身不會更新引用，這個端點會掃過全模型的量值、計算資料行、計算表、計算項目與 RLS 篩選式，把引用一起改掉。

回傳完整的 Rewrites 清單（每一筆的 Before／After）。

一律先用 DryRun: true 檢視改寫清單，確認沒有誤改再實際執行。 { "ObjectType": "measure", "TableName": "量值", "OldName": "銷售額", "NewName": "銷售總額", "DryRun": true }

第柒部：關聯線 POST · 建模的另一半工作

POST

/api/upsert-relationship

建立或更新關聯

依來源／目標的表與欄位比對，存在就更新、不存在就新建。可設定基數（one／many）、跨篩選方向（single／both／auto）、是否啟用。

{ "FromTable": "銷售", "FromColumn": "DateKey", "ToTable": "日期", "ToColumn": "DateKey", "FromCardinality": "many", "ToCardinality": "one", "CrossFilterDirection": "single" } 建立後需要 refresh + calculate 才能用於查詢。
POST不可復原

/api/delete-relationship

刪除關聯

以來源／目標的表與欄位四元組指定要刪的關聯線。

第捌部：進階建模 Power Query · 計算群組 · RLS

POST

/api/update-m

已移除（2026-08-06）— M 腳本唯讀

呼叫會回 410。要讀 M 請用 GET /api/schema 的 MQuery 欄位（PowerShell：Get-PbiMQuery）。

為什麼拿掉：Power BI Desktop 的 Power Query 文件與 TOM 模型是兩份獨立的東西。用 TOM 改 M 只動到模型那份，Desktop 那份不會跟著變；兩邊一失步，Desktop 就永久顯示「查詢中有暫止的變更尚未套用」，按「套用變更」是拿舊 M 去跑，橫幅又回來，陷入死迴圈。
正確做法：把完整的 let...in 交給使用者，請他在 Power Query 編輯器的進階編輯器貼上，再「關閉並套用」。
POST

/api/upsert-expression
/api/delete-expression

M 參數與共用函式

建立、更新或刪除模型層級的 Power Query 共用運算式。

POST

/api/upsert-calc-group

計算群組

時間智慧的殺手鐧：一組計算項目就能讓所有量值支援 YTD／MTD／YoY，不必為每個量值手寫衍生版本。

前提：模型的 DiscourageImplicitMeasures 必須為 true（引擎強制）。
開啟後使用者無法再把數值欄位直接拖進視覺自動彙總，一律得改用量值。這是模型層級的行為改變，務必先取得同意。
POST

/api/upsert-calc-item
/api/delete-calc-item

計算項目

用 SELECTEDMEASURE() 代表被套用的量值。可指定排序 Ordinal 與格式字串運算式。

{ "TableName": "時間智慧", "ItemName": "YTD", "Expression": "CALCULATE(SELECTEDMEASURE(), DATESYTD('日期'[Date]))" } 新增項目後需要 refresh 該計算群組表，項目才會真的作用在量值上。
POST

/api/upsert-role
/api/delete-role

資料列層級安全性

建立或更新 RLS 角色與其資料表篩選規則。

TablePermissions 是整組取代：送什麼就是最終狀態，未列出的舊規則會被清掉。
POST

/api/set-model-props

模型層級屬性

設定 DiscourageImplicitMeasures 與模型說明。

要把 DiscourageImplicitMeasures 改回 false，必須先刪掉模型中所有計算群組。

第玖部：批次 效能與交易語意

POST

/api/batch

一次連線、一次 SaveChanges

寫 20 個量值 = 20 次 HTTP + 20 次 SaveChanges() + 20 次模型重算。批次只重算一次。

更關鍵的是失敗語意：預設 StopOnError: true 且最後才存檔 — 任一步失敗，整批變更全部丟棄，模型維持原狀。只有在後續操作依賴前面結果「已生效」時才需要 SavePerOp: true（此時失敗不會回滾，回應會明確告訴你前幾個已經寫進去了）。

單次上限 200 個操作。支援 DryRun。

{ "Operations": [ { "Op": "upsert-measure", "Args": { "TableName": "量值", "MeasureName": "銷售總額", "Expression": "SUM(f[Amount])", "FormatString": "#,0" } }, { "Op": "upsert-measure", "Args": { "TableName": "量值", "MeasureName": "訂單數", "Expression": "COUNTROWS(f)" } } ], "StopOnError": true }

可用的 Op： upsert-measure、delete-measure、move-measure、 add-column、delete-column、set-column-props、 create-table、delete-table、 rename、upsert-relationship、delete-relationship、 upsert-calc-group、upsert-calc-item、delete-calc-item、 upsert-role、delete-role、upsert-expression、 delete-expression、set-model-props

沒有 update-m —— M 腳本唯讀，用了會回 410。原因見上方 /api/update-m 那張卡。

第拾部：視覺層注入 檔案驅動 · 最危險的端點

POST會強制關閉 PBI

/api/inject-visual

繞過介面限制，直接寫入 .pbip 底層

送出 Ctrl+S → Process.Kill() 強制砍掉目標那一個 Power BI Desktop → 寫入 visual.json（可含全新分頁的 page.json 並更新 pages.json）→ 重新開啟同一個檔案。

報表定義資料夾由目標實例推導： X:\proj\name.pbip → X:\proj\name.Report\definition。 不再依賴設定檔，所以不會發生「關掉你正在做的檔案、打開另一個」。

已內建的防護：

  • PageId／VisualId 必須是 20 位 hex（防路徑注入）
  • VisualJson 必須是合法 JSON
  • 寫入路徑必須落在該 PBIP 專案資料夾內（防路徑穿越）
  • 選用的 Security:AllowedBasePaths 白名單：設了就必須同時符合
  • 目標不是 PBIP 時直接中止 — 視覺注入只適用展開成資料夾的專案
  • 只關掉目標那一個實例 — 其他開著的 PBI 不受影響
強制中止仍有未存檔資料遺失的風險。使用前務必先確認，並手動存檔備份。
